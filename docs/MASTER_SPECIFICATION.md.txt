# PART I

# 1 Vision

Green Logistics Attendance Management System is the first software module of the future Green Logistics Platform.

The purpose of this system is to provide reliable, real-time employee attendance management while maintaining complete historical records of every attendance event.

The system is designed for long-term scalability.

Every architectural decision must support future expansion without redesign.

---

# 2 Primary Goals

The system shall:

• Receive attendance events from the access control system.

• Process attendance events.

• Store all events permanently.

• Calculate employee attendance.

• Detect late arrivals.

• Track employee office exits.

• Track employee returns.

• Calculate total office absence time.

• Display real-time employee status.

• Generate attendance reports.

• Provide historical records.

• Integrate with future CRM.

---

# 3 Core Principles

The architecture follows these principles.

Documentation First.

Business Rules First.

API First.

Event Driven.

Permanent History.

No Data Loss.

Modular Design.

Scalable Architecture.

Single Responsibility.

Security by Design.

---

# 4 System Philosophy

The system never guesses.

The system never assumes.

The system only processes verified events received from the access control system.

Every calculation originates from recorded events.

Every event remains permanently stored.

The history is immutable.

Corrections never overwrite history.

Corrections create additional records.

# 7 Attendance Engine

## Overview

The Attendance Engine is the core component of the Green Logistics Attendance Management System.

Its responsibility is to transform raw attendance events into structured attendance sessions.

The Attendance Engine never communicates directly with users.

Its only responsibility is business processing.

---

## Responsibilities

The Attendance Engine shall:

• Receive validated attendance events

• Identify employee

• Determine employee shift

• Create attendance sessions

• Update attendance sessions

• Detect late arrivals

• Calculate office absence intervals

• Maintain employee current status

• Generate dashboard information

• Store all attendance events

• Produce audit information

---

## Input

The engine receives only validated events from the Integration Layer.

Example:

Employee ID

Timestamp

Direction (IN / OUT)

Device ID

Webhook Event ID

---

## Output

Attendance Session

Attendance Event

Absence Interval

Dashboard Update

Audit Log

Notification (if required)

The system shall maintain a list of employees.

The system shall allow:

Create Employee

Edit Employee

Deactivate Employee

Assign Shift

Assign Access Card

View Employee Information

Search Employee

---

## FR-002 Shift Management

The system shall support multiple work shifts.

Each shift shall contain

Shift Name

Start Time

End Time

Grace Period

Cross Midnight

Status

---

## FR-003 Attendance Processing

The system shall process every attendance event received from the Access Control System.

Every attendance event shall

Be validated

Be stored

Be assigned to an Attendance Session

Update Employee Status

Update Dashboard

---

## FR-004 Attendance Sessions

The system shall automatically create Attendance Sessions.

The system shall automatically close Attendance Sessions.

Only one Attendance Session may exist for one employee for one workday.

# APPENDIX AA

# User Interface Requirements

## General Requirements

The application shall provide a clean and responsive user interface.

The interface shall be optimized for desktop usage.

The interface shall support Full HD resolution (1920 × 1080) as the primary working resolution.

The interface shall automatically adapt to larger monitors.

---

## Dashboard Requirements

The Dashboard shall open immediately after successful login.

The Dashboard shall be the default application screen.

Dashboard data shall refresh automatically without requiring manual page reload.

The refresh interval shall be configurable.

Default refresh interval

5 seconds.

---

## Employee List

The Employee List shall display

Employee Photo

Employee Name

Department

Position

Current Shift

Current Status

First Entry

Last Activity

Late Status

Current Absence

Today's Total Absence

---

The Dashboard shall remain visible while the employee information is displayed.

The Employee Drawer shall contain

Attendance History

# APPENDIX AC

# Availability Requirements

Target Availability

99.9%

Application shall automatically recover after temporary failures.

Database connection shall automatically reconnect.

Webhook listener shall restart automatically if interrupted.

Background Scheduler shall automatically restart after unexpected failure.

---

# APPENDIX AD

# Security Requirements

Passwords shall never be stored in plain text.

JWT tokens shall expire automatically.

Inactive sessions shall expire automatically.

Every login attempt shall be logged.

Every failed login shall be logged.

API shall require HTTPS.

All sensitive configuration values shall be stored securely.

Audit Logs shall be protected from modification.

---

Every source code module shall contain descriptive comments.

Every public API endpoint shall be documented.

Every database table shall be documented.

Every business rule shall be documented.

Every configuration option shall be documented.

The implementation shall always remain synchronized with this specification.
