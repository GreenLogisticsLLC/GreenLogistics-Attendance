# Database Constraints

Every Primary Key uses UUID Version 4.

Every Foreign Key uses ON DELETE RESTRICT.

Attendance history is immutable.

Attendance Events cannot be updated.

Attendance Sessions cannot be deleted.

Audit Logs cannot be deleted.

Webhook Logs cannot be deleted.

Notifications cannot be physically deleted.

---

# Database Performance Rules

Dashboard queries shall use indexed columns only.

Attendance processing shall use indexed lookups.

Employee lookup shall use card_number.

Attendance Session lookup shall use employee_id + work_date.

Webhook duplicate detection shall use webhook_id.

Reports shall use work_date indexes.

No table scan is allowed during normal attendance processing.

---

End of Database Index Strategy

# Decision DBD-003

Attendance Events are immutable.

Once stored, an Attendance Event shall never be modified.

Corrections shall create additional records.

Original records remain unchanged.

---

# Decision DBD-004

Attendance Sessions represent one scheduled work shift.

A session begins with the first ENTRY.

A session ends with the final EXIT.

One employee may have only one Attendance Session for the same shift on the same Work Date.

# Decision DBD-005

Absence is calculated only from EXIT and ENTRY events.

ENTRY

↓

No other event affects absence calculations.

Late status is calculated once.

Only the first ENTRY event determines lateness.

Subsequent ENTRY events shall not recalculate lateness.

---

# Decision DBD-007

Dashboard is read-only.

Dashboard never performs calculations.

Dashboard only displays processed information received from the Backend.

---

# Decision DBD-008

Database stores facts only.

The database stores

Attendance Events

Attendance Sessions

Absence Intervals

Notifications

Audit Logs

Webhook Logs

The database shall not store calculated temporary values unless required for performance.

---

# Decision DBD-009

Webhook processing is idempotent.

Business processing shall occur only once.

Duplicate requests shall be logged.

---

# Decision DBD-010

Historical information is permanent.

Attendance history shall remain available for the lifetime of the system.

Historical information shall never be removed during normal operation.

---

# Decision DBD-011

The database shall remain independent of the user interface.

Changes to Reports shall not require database changes.

# Decision DBD-012

## Transaction Rules

Every migration shall execute inside one transaction.

If any statement fails

ROLLBACK

shall be executed.

No partial migration is allowed.

---

## UUID Rules

Every Primary Key shall use

gen_random_uuid()

No sequential identifiers shall be used.

---

## Timestamp Rules

Every table shall include

created_at

updated_at

except immutable log tables where only

created_at

is required.

---

## Foreign Key Rules

All Foreign Keys shall use

ON DELETE RESTRICT

ON UPDATE CASCADE

---

## Index Rules

Create indexes immediately after table creation.

Composite indexes shall be created after single-column indexes.

Duplicate indexes are prohibited.

---

## Seed Data Rules

Seed data shall be idempotent.

Running the seed script multiple times shall not create duplicate records.

---

## Validation Rules

After migration completes, verify

All tables exist.

All indexes exist.

All foreign keys exist.

All constraints exist.

All views exist.

All triggers exist.

Required seed data exists.

Verified Backup

Successful Migration

Successful Validation

Successful Rollback Test

Administrator Approval
