# Интеграция партнёра — Legacy Reader (2 эндпоинта)

Документ для стороннего разработчика. Описывает **ровно две интеграции** между вашим сервером и нашим:

1. **Ingest** — *вы → нам*: вы присылаете нам билеты (карты доступа) пачками. Вы реализуете **отправку**.
2. **Webhook** — *мы → вам*: после каждого успешного прохода (enter/exit) мы уведомляем ваш сервер. Вы реализуете **приём**.

Никакой авторизации с физического считывателя не требуется — он общается только с нами.

---

## Токены авторизации (важно — два разных)

| Токен | Кто выдаёт | Где используется | Как хранится у нас |
|---|---|---|---|
| **Ingest-токен** | **Мы** (генерим, отдаём вам) | Вы кладёте его в `Authorization` при вызове нашего `/api/legacy/ingest` | SHA-256 хеш (плейнтекст не храним) |
| **Webhook-токен** | **Вы** (придумываете, отдаёте нам) | Мы кладём его в `Authorization` при вызове вашего webhook-URL | Зашифрованно |

Оба передаются по схеме `Authorization: Bearer <токен>`. Вы также сообщаете нам **URL вашего webhook-приёмника**.

---

## 1. Ingest — отправка билетов нам (вы → нам)

Вы вызываете наш эндпоинт, чтобы создать/обновить билеты. Мы делаем **upsert по `external_ref`** (идемпотентно): повторная отправка того же `external_ref` обновляет существующую запись, дублей не создаёт.

### Запрос
```
POST https://<наш-домен>/api/legacy/ingest
Authorization: Bearer <ingest-токен>
Content-Type: application/json
Accept: application/json
```

### Тело запроса
> Комментарии `//` ниже — только для пояснения. **В реальном запросе отправляйте чистый JSON без комментариев.**
```jsonc
{
  "tickets": [                                     // массив билетов — ОБЯЗАТЕЛЬНО, максимум 500 за запрос
    {
      "external_ref": "ORD-10045",                 // ОБЯЗАТЕЛЬНО — ваш id билета; ключ обновления (upsert)
      "token":        "0aab3c5d",                  // ОБЯЗАТЕЛЬНО — токен/UID карты; сверяется при сканировании
      "type":         2,                           // ОБЯЗАТЕЛЬНО — 1 = master (всегда пускает), 2 = обычный
      "valid_from":   "2026-06-22T09:00:00+04:00", // опционально — начало действия (нет/null = без нижней границы)
      "valid_until":  "2026-06-30T23:59:59+04:00", // опционально — конец действия, должно быть >= valid_from (нет/null = бессрочно)
      "max_entries":  10,                          // опционально — лимит входов (нет/null = без лимита)
      "is_active":    true,                         // опционально — false = отозвать билет (по умолчанию true)
      "days_of_week": 31,                          // опционально — маска дней Пн..Вс (31 = Пн–Пт; нет/null = любой день)
      "daily_from":   "09:00",                     // опционально — начало дневного окна (нет/null = весь день)
      "daily_to":     "18:00"                      // опционально — конец дневного окна, должно быть >= daily_from
    }
  ]
}
```
Минимально достаточный билет — только три обязательных поля: `external_ref`, `token`, `type`. Остальное можно не присылать.

`tickets` — массив, **обязателен**, **максимум 500 элементов** за один запрос. Если билетов больше — отправляйте несколькими запросами.

### Поля одного билета

| Поле | Тип | Обязательность | Описание |
|---|---|---|---|
| `external_ref` | string (≤120) | **обязательно** | Ваш идентификатор билета. **Ключ обновления** — по нему мы апдейтим. |
| `token` | string (≤64) | **обязательно** | Токен доступа/UID карты. Можно слать в формате `0x_0a0x_ab...` или чистый hex — мы нормализуем. Это значение сверяется при сканировании. |
| `type` | integer | **обязательно** | `1` = master (минует окна/лимит, всегда пускает), `2` = обычный билет. |
| `valid_from` | datetime (ISO 8601) | nullable | Начало действия. `null` = без нижней границы. |
| `valid_until` | datetime (ISO 8601) | nullable | Конец действия. Должно быть `>= valid_from`. `null` = без верхней границы. |
| `max_entries` | integer (≥1) | nullable | Лимит входов. `null` = без лимита. |
| `is_active` | boolean | необязательно | `false` = **отозвать** билет. Если не прислать — на создании `true`, на обновлении не меняется. |
| `days_of_week` | integer (0–127) | nullable | Битовая маска дней: Пн=бит0(1), Вт=бит1(2), Ср=4, Чт=8, Пт=16, Сб=32, Вс=64. Напр. `31` = Пн–Пт. `null` = любой день. |
| `daily_from` | string `"ЧЧ:ММ"` | nullable | Начало дневного окна (24ч). `null` = весь день. |
| `daily_to` | string `"ЧЧ:ММ"` | nullable | Конец дневного окна. Должно быть `>= daily_from`. Окно «через полночь» пока не поддерживается. |

> Отзыв билета — присылайте тот же `external_ref` с `"is_active": false` (не «молча удаляйте» на своей стороне; мы об удалении не узнаем).

### Ответ — `200 OK`
```json
{
  "received": 1,
  "created": 1,
  "updated": 0,
  "errors": []
}
```
| Поле | Описание |
|---|---|
| `received` | сколько билетов пришло в запросе |
| `created` | сколько создано |
| `updated` | сколько обновлено |
| `errors` | проблемные элементы (остальные при этом применяются) |

Пример с ошибкой по элементу:
```json
{
  "received": 2, "created": 1, "updated": 0,
  "errors": [
    { "index": 1, "external_ref": "ORD-10046", "reason": "TOKEN_CONFLICT" }
  ]
}
```
`TOKEN_CONFLICT` — тот же токен (`token`) уже привязан к другому билету в этом профиле (один токен = один билет).

### Прочие коды ответа
| Код | Когда | Тело |
|---|---|---|
| `401` | нет/неверный ingest-токен | `{ "code": "LEGACY_INGEST_UNAUTHORIZED" }` |
| `422` | тело не прошло валидацию (нет обязательных полей, >500, плохой формат) | стандартные ошибки валидации Laravel |

## 2. Webhook — приём событий от нас (мы → вам)

После **каждого успешного прохода** (enter или exit) мы делаем POST на ваш webhook-URL. **Отказы (reject) не отправляются.**

### Что мы шлём
```
POST <ваш webhook-URL>
Authorization: Bearer <webhook-токен>     (только если вы его задали)
Content-Type: application/json
Accept: application/json
```

### Тело (payload)
> Это то, что **МЫ присылаем вам** (вы принимаете). Комментарии `//` — для пояснения.
```jsonc
{
  "profile_id":   "186",                        // id профиля (сайта/партнёра)
  "device_id":    "12",                          // id считывателя
  "token":        "0aab3c5d",                    // токен/UID карты (нормализованное значение)
  "external_ref": "ORD-10045",                   // ваш id билета (может быть null, если у билета его нет)
  "decision":     "enter",                       // "enter" или "exit" (отказы не присылаем)
  "direction":    "in",                          // "in" или "out" (может быть null)
  "scanned_at":   "2026-06-22T11:03:21+04:00"    // момент прохода, ISO 8601
}
```

| Поле | Тип | Описание |
|---|---|---|
| `profile_id` | string | Идентификатор профиля (сайта/партнёра). |
| `device_id` | string | Идентификатор считывателя. |
| `token` | string | Токен доступа/UID карты (нормализованное значение). |
| `external_ref` | string \| null | Ваш id билета. `null`, если у сработавшего билета его нет. |
| `decision` | string | `"enter"` или `"exit"`. |
| `direction` | string \| null | `"in"` или `"out"`. |
| `scanned_at` | string (ISO 8601) | Момент прохода. |

### Что должен вернуть ваш сервер
- **Любой `2xx`** = принято (мы помечаем доставленным).
- Любой другой код или таймаут → мы **повторим** (до **3 попыток**).
- Таймаут ожидания ответа — **8 секунд**, отвечайте быстро.
- **Приём должен быть идемпотентным** — из-за ретраев одно и то же событие может прийти повторно (ориентируйтесь на `external_ref` + `scanned_at` + `decision`).

---

## Форматы (сводно)
- **Дата-время** (`valid_from`, `valid_until`, `scanned_at`): ISO 8601, желательно с таймзоной, напр. `2026-06-22T11:00:00+04:00`.
- **Время окна** (`daily_from`, `daily_to`): `"ЧЧ:ММ"`, 24-часовой формат.
- **`type`**: `1` master, `2` обычный.
- **`days_of_week`**: битовая маска Пн..Вс (Пн=1, Вт=2, Ср=4, Чт=8, Пт=16, Сб=32, Вс=64).
- Кодировка — UTF-8, тело — JSON.
